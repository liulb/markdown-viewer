## 2. 单一用途说明（Single purpose）

> 本扩展的唯一用途：在浏览器中查看 Markdown 文件的渲染结果。它检测浏览器以纯文本形式展示的 Markdown 文件，将其渲染为带目录导航的阅读页面，并允许用户以同样方式浏览本地文件夹中的 Markdown 文档集合。所有处理均在本地完成。

## 3. 权限理由（Permission justification）

**`storage`：**
> 用于保存用户在扩展弹窗中的显示偏好（主题模式、视图模式、目录是否自动展开），通过 chrome.storage.sync 存储且仅服务于本扩展的显示设置。

**`scripting` + 主机权限 `<all_urls>`：**
> 用户可能从任意域名打开 Markdown 文件（raw.githubusercontent.com、各代码托管/网盘直链、企业内网文档系统、file:// 本地路径等），扩展无法预先知道来源域名。扩展以一个约 2KB 的内容脚本在所有页面进行轻量检测：仅当页面是浏览器以纯文本形式展示的 Markdown（Content-Type 为 text/markdown 或 text/plain 且扩展名为 .md 等）时，才通过 chrome.scripting 向该标签页注入渲染库。对普通网页不注入、不修改、不读取其内容，也不与任何服务器通信。因此需要宽泛主机权限以实现"打开即渲染"的核心功能。

**可选：若审核要求收窄权限，备选方案**
> 将 `<all_urls>` 改为 `optional_host_permissions`，首次遇到 .md 页面时请求用户授权（需同步修改 detector 逻辑）。会牺牲"开箱即用"体验，可作为被拒后的折中。

## 4. 数据使用披露（Privacy tab）

- 是否收集或使用个人数据？→ **否**（我们的扩展不向开发者传输任何数据；chrome.storage.sync 中仅存用户的显示偏好，属于用户自己的浏览器同步，不属于"收集"）
- 如被要求说明"读取网页内容"（因内容脚本存在）：→ 扩展读取页面的纯文本内容仅用于判断其是否为 Markdown 文件并本地渲染展示；内容不会离开用户设备、不会传输给开发者或第三方。

## 5. 发布设置建议

- 可见性：公开（Public）；也可先"不公开（Unlisted）"试审核水
- 分布地区：默认全部
- 首次审核含宽泛主机权限会走人工审核，通常 1–4 周；后续小版本更新较快
- 审核期间可在控制台查看状态；被拒会给出具体条款，按回复修改后重新提交
